AtomRTL's generation graph

Pulled directly from build_graph().get_graph().draw_mermaid() — the real compiled graph, not a diagram reconstructed from reading the source. Five deterministic Python nodes do the bookkeeping; three LLM nodes each get a small, fresh, tool-free prompt.

	__start__ --> parse_spec;
	parse_spec --> plan;
	plan --> generate;
	generate --> write_code;
	fix --> write_code;
	write_code --> check;
	check --> route;
	route -.->|pass / budget exhausted| finalize;
	route -.->|errors| fix;
	route -.->|stuck: same error N times| generate;
	finalize --> __end__;

LLM node — fresh prompt, no tools, one code block back Python node — deterministic, no model call
parse_spec python Extracts the module name and port list straight from the spec text.
plan LLM One short pass sketching the implementation approach before any code is written.
generate LLM Writes the first full SystemVerilog attempt as one fenced code block.
write_code python Extracts the code block and writes TopModule.sv to disk.
check python Compiles with iverilog, lints with slang, checks the interface against the spec.
route python Decides next step: clean → finalize, errors → fix, same error repeated → restart from generate.
fix LLM Gets the diagnostics and the failing code, returns a corrected version.
finalize python Writes result.json with the pass/fail status and full attempt history.
Node identities and descriptions are AtomRTL's own (atomrtl/graph.py); the dotted edges out of route are its one conditional branch.
